## Задание 4: Проектирование продажи ОСАГО

### Результаты
- **Диаграмма с ОСАГО системой**: [Task4/InsureTech_C4_OSAGO.drawio.xml](Task4/InsureTech_C4_OSAGO.drawio.xml) *(основана на Event-Driven архитектуре из Task3)*
- **Техническое решение**: [Task4/osago-solution.md](Task4/osago-solution.md)

### Ключевые решения
- Выделенный сервис `osago-aggregator` для взаимодействия со страховыми компаниями
- Real-time обновления через WebSocket для немедленного отображения предложений
- Redis кэш для управления состоянием 2,500+ одновременных заявок
- Полный набор паттернов отказоустойчивости: Rate Limiting, Circuit Breaker, Timeout, Retry
- Горизонтальное масштабирование с поддержкой множественных экземпляров сервисов
- Максимальное время ожидания 60 секунд с graceful degradation

## Задание 5: Проектирование GraphQL API

### Результаты
- **GraphQL схема**: [Task5/client-info-graphql-schema.graphql](Task5/client-info-graphql-schema.graphql)
- **Примеры запросов**: [Task5/graphql-query-examples.md](Task5/graphql-query-examples.md)

### Ключевые решения
- Переход от множественных REST endpoints к единому GraphQL endpoint
- Решение N+1 problem: объединение запросов клиент + документы + родственники в один
- Точная выборка полей: снижение трафика в 5 раз за счет запроса только нужных данных
- Типизированная схема с поддержкой 500+ атрибутов клиента
- Гибкость для разных сценариев: ОСАГО, страхование жизни, мобильные приложения
- Снижение RPS в 3 раза при сохранении всей функциональности
